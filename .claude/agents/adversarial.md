## 必测用例（至少覆盖这些，鼓励自己加）

### 畸形文件
- 0 字节文件；把 `.txt` 改名成 `.jpg`；截断到一半的 JPEG
- 头部完好但数据段损坏的 PNG；嵌套 zip 炸弹式的超大 PNG（1×1 亿像素声明）
- CMYK 色彩空间的 JPEG；16-bit PNG；带 alpha 的 JPEG（伪造）
- 动图 GIF / WebP 动画；HEIC；多帧 TIFF
- 文件名含中文、emoji、超长路径、Windows 保留名（`CON.jpg`）

### 极端尺寸
- 1×1 像素；1×10000 极端长条；12000×12000 超大图
- 宽高比 1:100；正方形恰好等于目标规格尺寸

### 内容极端
- 全黑图 / 全白图 / 纯噪点
- 0 张人脸；50 张人脸的合影；人脸只露一半在画面边缘
- 戴口罩 / 大墨镜 / 侧脸 90° / 倒置的人脸
- 背景与肤色高度接近（浅色背景 + 浅肤色）
- EXIF Orientation = 6/8 的手机竖拍图（**极易出错，必测**）

### 操作序列
- 抠图进行中立刻换图；连点保存 20 次；处理中旋转屏幕
- 处理中切后台再回来；处理中杀掉再启动（状态是否损坏）
- 快速连续切换 7 个规格；拖拽裁剪框到极限位置来回甩
- 相册权限被拒绝后的行为；保存时磁盘满

### 资源压力
- 连续处理 30 张大图，观察内存曲线是否单调上升（泄漏）
- 低内存设备模拟（模拟器限制 RAM）

## 判定

任一用例导致以下情形 = 一条 CRITICAL：
- 进程崩溃 / ANR（无响应 >5s）/ 黑屏 / 界面卡死
- 产出损坏的图片文件 / 尺寸错误的图片 / 保存到了错误位置
- 未捕获异常穿透到 UI（红屏、英文堆栈暴露给用户）
- 内存持续增长不回落

其余为 MAJOR / MINOR。
