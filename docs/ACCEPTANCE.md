# 验收标准（Definition of Done）

**主会话是本文件的唯一写入者。任何 agent 修改本文件 = 立即 FAIL 并终止该阶段。**

全自动模式下没有人工判断，所有 gate 必须是脚本可判的。凡是写不出判定脚本的标准，
一律不作为 gate（可以写进 RUBRIC 交给 visual-critic，但不作为硬门禁）。

判定程序：`tools/gate/gate_G<n>.dart`，退出码 0 = PASS，非 0 = FAIL。
由 `gatekeeper` 执行，**实现类 agent 无权运行也无权修改**。

## G2B-P0 — 摆正估计准确性（2026-09-17 新增）

存在理由（真实事故，非理论风险）：2B.8 是自证式夹具，估角器错 5° 也照样 PASS。
结果 v1.2.1 上线后，用户两张真实照片的成片肉眼可见歪斜——`2.jpg`（一张本来就
竖直的蓝底证件照）被**转歪 3.7°**，`1 (2).jpg` 真值 −4.4° 却**一点都不转**。
全流程 16 项 G4 门禁无一拦截。本组即为补上这个洞。

**判据适用域（2026-09-17 用户裁定，随 10° 摆正死区一起生效）**

用户把摆正死区定为 **10°**（`kRollDeadZoneDeg`，`lib/core/imaging/crop_geometry.dart`）：
**真值倾角绝对值 ≤ 10° 的照片一律不旋转**，只有明显拍歪的 (10°, 30°] 才摆正。这不是测量结论，
是产品决定——普通拍摄的轻微倾斜不值得为它重采样，更不值得为它把裁剪框转出原图。
上限仍是 `kMaxRollDeg` = 30°。

本节判据据此分两档，**两档都要报，不得只报其一**：

- **死区内（|真值| ≤ 10°）：判"引擎没有动它"。** 成片残余应 ≈ 真值倾角
  （|残余 − 真值| ≤ 1.5°），**不是** ≈ 0。**把一张死区内的照片转正同样是 FAIL**——
  本次事故里 `2.jpg`（本来竖直）被转歪 3.7° 就属于这一类，由 P0.6 拦。
- **死区外（|真值| > 10°）：判"必须摆平"。** 成片残余 |residual| ≤ 1.5°。

原来的分界（|真值| > 1.5°）是旧产品行为的产物（那时要求小角度也摆正），已被本次裁定取代。

**分档一律按真值（外部锚点），不得按引擎自报的角。** 按自报角分档会让**样本集本身变成测量的函数**：
引擎的估计值决定哪些样本进判据，而它天然会把"真值刚出死区、估计刚进死区"的样本移出 ——
`c11_d-10` 正是这类（真值 −10.11° 出界，成片实测就是歪着 10.11°，却会被移进死区内按"没被乱动"通过）。
**唯一例外是 P0.6 的主判据**：它问的是"引擎有没有照自己报的角行事"，属**符合性**检查，
按自报角判才是该问题的正确口径；但它是自洽性检查，**不构成正确性证据**（见下）。

**边界带（对 P0.1a / P0.1b / P0.3a② / P0.3b 一律生效）**：真值落在 **9°–11°** 的样本
**只报数、不判 FAIL**。理由：那里"该不该转"由一个 0.4° 量级的估计误差决定
（语料实测估计误差范围 −0.091°…+0.477°），拿真值去罚它就是**把噪声记成实现方的错**。
带宽 ±1° 大于实测误差的 2 倍。已知落在带内：`c11_d+10`（真值 9.89 → 估计 10.283，**转了**）、
`c11_d-10`（真值 −10.11 → 估计 −9.633，**没转**）——**两个方向都真实发生过**。
带内样本必须逐条列出真值 / 估计 / 施加角 / 残余，**不得静默丢弃**。

**口径后果，必须写进每轮报告**：`out/P0_truth.json` 的 12 条锚点、1 条 `straight`、
9 条 `uprightSynthetic` **真值全部落在死区内**（最高是 `c08` 的 −8.01°），
故"必须摆平"这一半在本语料上只由**死区外的夹具**承担（全规格 19 行，门禁规格
`cn_big_1inch` 按 id 去重后 **15 条**，其中 4 条落在 9°–11° 带内 ⇒ 实际参与判定的 **11 条**），
真实照片不再参与。**报数一律报 15 / 11 这两个口径，不得写成 19。**
这是产品定义变化带来的覆盖收缩，不是实现变好；**不得把它当成通过率上升来讲**。

**P0.6 的量具故障必须逐条挂牌。** 残余量具在若干样本上本身不可信（实测：未摆正状态下
`c08_d+10` 族读出 13.657°、`c08_d-10` 读出 17.937° 这类离谱值）。这类**必须逐条列出并归类**，
不得静默通过、也不得静默判失败——**"量具坏了"与"引擎真的乱转了"在人读的报告里长得一样**，
而 P0.6 正是唯一会去读"死区内成片残余"的判据。

**P0.6 主判据只证明自洽，不证明正确——报告里必须这么标。** `straightenDeg` 由
`planRotation(rollDeg: face.rollDeg)` 直接算出（`compose_engine.dart:232-249`，**两者同源**），
所以主判据是**拿估计核估计**：它证明的是"死区判断按规格实现、报告的角度与施加的角度一致"，
**不证明估计正确，也不证明旋转真的落到了像素上**。故：

- 主判据那一行必须写明「**自洽性检查：证明引擎遵守自己的规则，不构成正确性证据**」；
- **不得单独出现**，必须与次判据（成片端到端残余，Python 侧独立量具）同报；
- 次判据因量具故障不可用的样本，**不得靠主判据通过**，按「量测失效」逐条挂牌。

这不是本项特有的弱点，而是**任何"用引擎自报的量去核引擎"的判据的共性**：
它抓得住"判错变量""报告与行为不一致"这类实现错误（这也是它存在的理由），
但正确性必须另有一条**不经过生产代码**的路径——本项是成片端到端残余，
P0.3a① 是真值回归。

**计分口径（2026-09-17 主会话裁定，防作弊）**

> **判据冻结声明（非判据变更）**：G2B-P0 的全部条目与计分口径**冻结于 commit `6f01e6e`**。
> 在此之前它曾在门禁运行期间被连续修改 4 次（03:23 / 03:24 / 03:39 / 03:47），
> 直接导致 gatekeeper 第 1 轮判决作废——它按改动前的草稿实现，且判据从"读
> `straightenDeg`"改成了"只认成片端到端残余"，等于判了一个新法典明令不作判据的量。
> **这是主会话的流程错误**：判据必须先冻结、再开跑。
> 自此以后：**本轮内不得再改判据**；确需修改时，改完必须**作废当轮、从第 1 轮重跑**，
> 并在 `out/GATE_P0_r*.md` 里写明是哪一次修改导致重跑。

1. **`unavailable` 在死区外一律不计为通过**（P0.1a / P0.3a）。否则一个"永远返回测不出 + 0.0"的实现，在死区外的夹具上不转、残余就是真值本身，会免费通过——而这恰恰是把本轮事故重演一遍。**死区内反过来**：`unavailable` 与"测得准但不施加"的成片结果相同，不构成缺陷。
2. **但 `unavailable` 也不是一律有罪**：真正测不出的样本（暗光、闭眼、多人小脸）返回 0 是诚实行为，好过给一个错的角。所以判据落在**条件覆盖率**（P0.1b / P0.3b）：**只要这张图确实需要摆正（\|tilt\| > 10°，即死区外），就必须给出 `pupil` 估计**；不需要摆正的图返回 `unavailable` 无害。
   - 分界取 **10°（死区）**：2026-09-17 用户裁定前这里写的是 1.5°，理由是与 P0.1a 的残差容差同值、"不转导致的残余本来就能过线"。那条理由依赖"残余 ≤ 1.5° 即合格"，而死区把合格线改成了**真值本身**（死区内不转才是对的），故 1.5° 的前提已不成立，分界必须跟着产品定义走，不能再按残差容差推。超过死区仍放弃，用户拿到的就是一张肉眼可辨的歪照（如真值 −18.01° 的 `c08_d-10`），必须记 FAIL 而不是"诚实降级"。若最终证明某类真难样本无法达标，由主会话带证据找用户裁定是否接受**有记录的**缺口，**不许在门禁里悄悄放行**。
3. ~~**P0.2 单独要求 `pupil`**：竖直样本若也允许 `unavailable` 通过，那么"永远放弃"策略就能免费拿下这一项。~~
   **2026-09-17 作废**：该策略在死区定义下已不解自破——死区外（|真值| > 10°）不估计、不施加，残余就是真值本身，P0.3a / 2B.8 直接拦下。留着这条会与 P0.1b 矛盾，故删。
4. **两组判据必须同时成立**：覆盖率逼"不能放弃"、残差逼"不许测错"——放宽门限换取覆盖率会让 P0.1a 的残差爆掉，两者互相牵制。**任何一轮不得只报其中一个数。**
5. 硬判据一律用**成片端到端残余**（口径无关）；`ComposeDiagnostics.straightenDeg` 只作诊断与定位，不作判据。
   - **2026-09-17 限定（管的是准确性判据，不是全部判据）**：P0.6 的**主判据**是**符合性**检查
     ——"引擎有没有照它自己报的角行事"，它以 `straightenDeg` / `straightened` 为输入，**不违反本条**。
     但它受两条硬约束：必须标明「自洽性检查、不构成正确性证据」，且**不得单独出现**，
     必须与成片端到端残余的次判据同报。
     这与 `:108-111` 记的 r1 作废原因**不冲突**：那次作废是因为拿 `straightenDeg` 当**准确性**判据

6. **锚点去重**：锚点语料共 **12 条**（`p1`、`c01`–`c08`、`c10`、`c11`、`c12`；`p2` 同现于 `anchors` 与 `straight`，成片台按 id 合并后归入 `straight`，**不计入锚点栏**）。其中 `c03`/`c04` 是同一张照片的两个分辨率副本（逐像素 mean\|diff\|=2.74）——**故实际覆盖 11 张不同照片**。仍满足"≥8 张"的要求，报告与判据里的样本数一律按 **11 张不同照片**表述，不得虚增。
   - **2026-09-17 订正（r2 开跑前的**事实**订正，非阈值变更）**：原文另称 `c10`/`c11`/`c12` 是同一张五人合影的不同裁切——**该理由不成立，已删除**。三者是**同一场景的三张不同照片**，**不去重、各自计数**。复核方法：ECC 欧氏对齐后**只统计结构像素（Sobel 梯度 > 25）**（平坦蓝底会把相似度整体抬高，必须剔除），并以**已知同图对** `c03`/`c04` 标定两端：

     | `c10`/`c11` | 11.3% | 33 |

7. **样本不得静默消失**：每轮的锚点/夹具样本数必须与 `out/P0_truth.json` 一致。任何"不可计分"的样本必须**逐条列出并归类**（抠图失效 / 量测失效 / 其他），且在**总数与通过数里同时显式扣除**。

## 防作弊条款（全自动模式的核心保护）

以下任一情形直接判定该阶段 **FAIL** 并计入循环预算，不得申辩：

1. 实现类 agent（ml-porting / imaging / ui-woodcraft / release）写入了 `test/`、`tools/gate/`、`docs/ACCEPTANCE.md`、`docs/RUBRIC.md`。
2. gate 脚本的 SHA256 与 gatekeeper 上一轮记录的不一致，且变更不是由 gatekeeper 自己做的。
   （首轮无 `out/hashes_prev.txt` 属正常，直接建立基线，不判 FAIL。）
3. 测试中出现 `skip:`、`@Skip`、注释掉的断言、被放宽的阈值常量。
4. 黄金集被删减、被替换成更容易的图片，或 `test/golden/` 下文件数减少。
5. 通过 catch-all 吞异常来让"0 崩溃"成立（`catch (_) {}` 空实现）。
6. 报告中声称达标但 gate 脚本未实际运行，或运行结果与报告不符。

## 循环预算

每个 gate **最多 3 轮**修复。第 3 轮仍 FAIL：
- 停止该阶段，产出 `out/BLOCKED_G<n>.md`，写清失败项、已尝试的方案、卡在哪
- **不得**降低阈值、**不得**跳过该 gate 继续下一阶段
- 全流程终止，等人工介入
